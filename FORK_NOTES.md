# Quillo fork notes

Quillo is a fork of `Silo-Server/silo-server`. This file lists every change to Silo's own code,
so upstream merges stay easy. Quillo's new features live in their own packages; anything listed
under "Core touchpoints" is an edit to a file Silo also changes.

Upstream remote: `upstream` → `https://github.com/Silo-Server/silo-server.git`.
Forked from upstream `1faea5e` (2026-11-01).

## Compatibility rules

- The database schema and `/api/v1` + `/api/v2` contracts stay compatible with stock Silo. Quillo
  tables go in their own migrations namespace (from Phase 2).
- Environment variables (`SILO_*`), paths (`/config`, `/opt/silo`), the Compose service name, and
  protocol headers (`X-Silo-*`) keep their Silo names, so an existing install switches by changing
  only the image line.
- The official Silo apps are the supported clients. Text that names them, or names services Silo
  itself runs (the shared skip-marker service, the push relay), keeps the Silo name.

## Merging upstream

```sh
git fetch upstream
git merge upstream/main
```

On a conflict in a file the string rebrand touched, take upstream's side, then re-run:

```sh
python3 scripts/quillo-brand/rebrand_strings.py
```

`--check` exits non-zero when a file still needs rebranding.

## Phase 2: addon manager

Quillo's own code:

- `internal/addons/` — manifest parsing and validation, the addon HTTP client, the
  `quillo_addons` store, the starter preset (Cinemeta, installed once on a fresh server), and the
  admin API handlers.
- `internal/addons/migrations/` — Quillo's migration set. It runs after Silo's, records versions in
  `quillo_goose_db_version`, and uses its own advisory lock, so it never collides with Silo's
  `migrations/sql`.
- `web/src/quillo/` — the Admin › Addons page and its API client.
- `scripts/quillo-route-inventory.sh` — regenerates `contracts/api/v2/route-inventory.json` in a
  Linux container (the generator needs linux/cgo).

Admin API (`/api/quillo/admin`, login + acting-admin required, outside Silo's `/api/v2` contract):
`GET/POST /addons`, `POST /addons/preview`, `GET /addons/presets`, `PUT /addons/order`,
`PATCH/DELETE /addons/{id}`, `POST /addons/{id}/refresh`. Errors use Silo's
`{"error", "message"}` envelope with a plain-English message.

## Phase 3: addon catalogs and search

- Home rows: installing a server-wide addon adds one home row per catalog that lists without an
  extra (Cinemeta: Popular and Featured, for movies and series), right after Continue Watching.
  Rows are ordinary `page_sections` rows of type `quillo_addon_catalog`
  (`{"addon","type","catalog"}`), so admins rename, move or hide them in Home Sections. They are
  created once per addon (`quillo_addons.home_rows_created`); removing the addon removes them.
- Catalog pages are fetched on demand and kept in memory (`internal/addons/catalogs.go`): fresh for
  20 minutes, then shown stale while a background refresh runs. A prewarm loop reloads every
  enabled addon's home-row catalogs every 15 minutes, so the home screen doesn't wait on addons.
- Titles become lightweight `media_items` rows (`internal/addons/materialize.go`) keyed by Silo's
  own deterministic content ids (TMDB/TVDB first, IMDb fallback). A title already in the catalog,
  found through `media_item_provider_ids`, is reused, so local files and addon results are one
  item. New items belong to no library, so library pages, Recently Added and the other library
  rows never list them. Posters are hotlinked (`https://` artwork paths pass through Silo's image
  resolution unchanged). `quillo_items` marks the items Quillo made.
- Search: the first page of a catalog text search also asks every enabled addon's searchable
  catalogs, in parallel, for at most 3.5 seconds, started before Silo's own search runs. Addon
  titles follow the local results, deduplicated, closest title matches first. Results are cached
  for 10 minutes.
- Viewers whose access is limited to certain libraries don't see addon titles (they belong to no
  library); maturity limits apply as for any item.

## Phase 4a: native metadata for addon titles

- Enrichment (`internal/addons/enrich.go`): a background worker (two at a time, most recently
  shown first) runs Silo's own `MetadataService.RefreshItem` on each Quillo-made item. Silo's
  TMDB/TVDB providers fill in cast and crew with photos, ratings, content ratings, trailers,
  studios, collections, and a series' seasons and episodes, as for a scanned file. Titles no
  provider knows keep their addon metadata; failures retry up to three times, hours apart.
- Streaming library (`internal/addons/streaming.go`): Silo lists seasons and episodes, and tracks
  Continue Watching and Next Up, only for titles in a library. Quillo creates one `mixed` library
  named "Streaming" (id in `quillo_meta.streaming_library_id`) with no folders, and adds each
  enriched title and its episodes to it. `catalog.RegisterVirtualLibrary` marks it so scans and
  membership reconciliation never touch it (they would otherwise drop every membership, since
  none has a file, and purge the items as orphans).
- Recently Added: addon titles and their Streaming memberships are dated 2000-01-01, so Recently
  Added rows list real library titles first.
- Artwork: addon titles keep provider links (TMDB/TVDB/metahub) instead of copies on disk. Silo's
  image-cache job queue is wrapped (`addons.HotlinkAddonArtwork`) to drop jobs for Quillo-made
  titles without a local file; a 10-minute sweep switches any stored copy back to its provider
  source, and Silo's hourly artwork cleanup deletes the displaced copies. Cast photos and local
  library artwork are cached as Silo normally does.

Not done yet: cleanup of Quillo-made items nobody has used for a while, handing an addon title
over to Silo when a local file for it appears (it stays dated 2000 and in Streaming), and
per-profile addons.

## Phase 4b: addon streams as versions

- When Silo reads a movie's or episode's files (detail page versions, playback start, alternate
  versions), `addons.StreamFiles` wraps Silo's file repository and first asks every enabled
  stream addon for the title (`movie/tt…` or `series/tt…:S:E`), in parallel, for at most 10
  seconds. Only `http(s)` url streams are used; torrent, YouTube and external-link streams are
  skipped. Results are ranked (resolution, then addon order, then the addon's own order), the best
  12 kept, and each saved as a `media_files` row in the Streaming library with a placeholder path
  `/quillo-stream/<hash>/<label>.<ext>`. `quillo_streams` holds the real URL and any request
  headers; it is never returned by the API. A title's streams are asked for again after 30 minutes
  (`quillo_stream_sets`).
- Labels: the version name is built from the addon's text, e.g. "2160p DV · 61.2 GB · Torrentio".
- Streams are not opened before playback: a debrid "resolve" link asks the service to fetch the
  torrent, so opening every listed link would add torrents nobody picked. Listing versions skips
  Silo's browse probe repair for streams (`addons.BrowseProbeEnsurer`); the stream that plays is
  probed by the playback handler's own ensurer at playback start.
- Ranking: streams the addon marks as ready on a debrid service ("[RD+]", "[RD⚡]", "⚡") come
  first, unmarked next, and not-yet-downloaded or unavailable ones ("[RD download]", "⬇️", "⏳",
  "❌") last; then resolution, addon order and the addon's own order.
- Playback: the apps play original files with their own engine, so most streams go through
  `original_http`: the server proxies byte ranges from the URL (`playback/quillo_remote.go`); the
  client only ever talks to Quillo. Every ffmpeg and ffprobe run (probe repair, seek anchors, HLS
  remux and transcode, the copy-safety scan) gets the placeholder path rewritten by
  `procgroup.RegisterArgRewriter` to a loopback URL,
  `http://127.0.0.1:<PORT>/api/quillo/internal/stream/<token>/<hash>`, which this server proxies to
  the real link. The token is random per process, the route answers loopback peers only, and the
  real link (which can hold a debrid token) never reaches a command line, a log or an error.
- A link that answers 4xx is hidden at once (`RegisterRemoteFailureReporter`), so the next play
  picks another version and the next view asks the addons again. Turning an addon off or removing
  it hides its streams.
- Jellyfin-compatible API: its detail service gets the same `StreamFiles` and browse probe
  wrapper, so Jellyfin clients (Infuse, Swiftfin, Streamyfin…) see addon streams as media sources
  and direct-play them through the same proxy. Their search only finds addon titles already in the
  Streaming library.
- Local files and addon streams for the same title are versions of one item; Silo's normal
  version choice decides the default (currently by quality, so an addon 1080p can beat a local
  720p).
- Dev tool: `scripts/quillo-test-addon` serves generated clips for a few IMDb ids and one dead link.
